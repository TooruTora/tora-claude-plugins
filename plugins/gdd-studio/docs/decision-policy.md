# GDD 스튜디오 — 유저 결정 질문 정책

> 유저 결정이 필요한 모든 지점에서 이 정책을 따릅니다. 산문으로 "~해도 될까요?"라고 묻고 답을 기다리는 대신, **AskUserQuestion 도구(구조화 선택지 UI)** 로 묻습니다.

## 핵심 원칙

- **유저 결정 대기 상태 = AskUserQuestion.** 유저가 골라야 진행되는 질문은 채팅 산문이 아니라 AskUserQuestion으로 띄운다. 유저는 클릭 한 번으로 답하고, 자유 입력이 필요하면 "Other"로 직접 쓸 수 있다.
- **개방형 질문은 예외.** 자유 서술이 본질인 질문(게임 비전 설명, 컨셉 브레인스토밍 등)은 산문 대화를 유지한다. 단, 예상 가능한 선택지가 2개 이상 나오는 순간부터는 AskUserQuestion이 우선이다.
- **가정으로 대체 금지.** 선택지를 만들기 애매하다고 임의로 가정하고 진행하지 않는다 — 애매하면 그것 자체를 질문으로 만든다.

## 적용 지점

### 1. 섹션 승인 게이트 (초안 → 검토 → 승인 → 작성)

초안을 채팅에 보여준 뒤, "이 섹션을 [파일경로]에 작성해도 될까요?"를 AskUserQuestion으로 묻는다:

- 옵션 예: `이대로 작성 (권장)` / `수정 후 작성` (description에 "수정할 부분을 Other 또는 다음 메시지로 알려주세요") / `이 섹션 건너뛰기`
- 스켈레톤 생성 확인("스켈레톤을 생성해도 될까요?")도 동일하게 적용한다.

### 2. 선택형 결정

다음처럼 답이 선택지로 떨어지는 질문은 모두 AskUserQuestion으로:

- 업데이트 모드에서 **어떤 섹션을 수정할지** (섹션 목록을 옵션으로, `multiSelect: true`)
- 설계 옵션 A/B/C 중 택일 (각 옵션의 장단점을 description에 요약, 권고안을 첫 번째에 두고 라벨 끝에 `(권장)`)
- 범위 판단(예: quick-note로 갈지 `/gdd-design`으로 전환할지), 플랫폼·장르 등 선택형 컨셉 질문

### 3. 세션 복원 시 열린 질문 해소

세션 시작/재개 시 `production/session-state/active.md`의 **"## 열린 질문"** 에 미해결 항목이 있으면, 새 작업을 진행하기 전에 그 항목들을 AskUserQuestion으로 순차 해소한다. 답이 나온 항목은 "핵심 결정사항"으로 옮기고 "열린 질문"에서 지운다.

## 질문 작성 규칙

- 한 번의 호출에 관련 질문을 **1~4개까지 묶어서** 묻는다 (섹션 승인처럼 단건이면 1개만).
- 옵션은 **2~4개**, 라벨은 1~5단어로 짧게, 장단점·함의는 description에 쓴다.
- 권고안이 있으면 **첫 번째 옵션**으로 놓고 라벨 끝에 `(권장)`을 붙인다.
- 복수 선택이 자연스러우면 `multiSelect: true` (예: 수정할 섹션 고르기).
- "Other" 옵션은 자동 제공되므로 직접 만들지 않는다.

## 서브에이전트 규칙 (중요)

기획 에이전트(`@game-designer` 등)는 서브에이전트로 실행되며 **AskUserQuestion 도구가 없다** — 유저에게 직접 질문 UI를 띄울 수 없다.

- 에이전트는 유저 결정이 필요한 항목을 **최종 리포트의 "결정 필요" 목록**으로 반환한다. 항목마다: 질문 1문장 + 선택지 2~4개 + 권장안과 근거.
- 에이전트 리포트를 받은 **메인 세션은 "결정 필요" 목록을 그대로 AskUserQuestion으로 유저에게 묻고**, 답을 받아 후속 작업(에이전트 재호출 또는 직접 반영)을 진행한다.
- 에이전트가 결정 없이 진행 가능한 기본값을 임의 선택하지 않도록, 위임 프롬프트에 "결정 필요 항목은 가정하지 말고 리포트로 반환하라"를 포함한다.

## 적용 범위

- **작성 커맨드** (`/gdd-concept`, `/gdd-design`, `/gdd-quick`): 워크플로우 내 모든 승인·선택 질문에 적용.
- **메인 세션의 대화형 작업**: 커맨드를 거치지 않은 수정 요청에서도 동일하게 적용.
- **읽기 전용 리뷰 커맨드** (`/gdd-review`, `/gdd-review-all`): 리포트 출력이 목적이므로 질문이 없는 것이 기본. 단, 리뷰 후 "지적 사항을 수정할까요?" 같은 후속 결정을 물을 때는 이 정책을 따른다.
