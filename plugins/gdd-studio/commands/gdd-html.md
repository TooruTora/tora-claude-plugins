HTML 표시본 동기화를 시작합니다.

대상: $ARGUMENTS

**이 커맨드가 하는 일:** 정본 md(`design/**/*.md`)를 기준으로 표시본 html(`design/html/**`)과 인덱스(`design/html/index.html`)를 정본과 일치하는 최신 상태로 되돌립니다. md는 절대 수정하지 않습니다 (읽기만).

**워크플로우:**

1. **대상 결정:**
   - `$ARGUMENTS`가 비어 있으면: **전체 동기화 모드** — `design/**/*.md` 전체 스캔 (`design/registry/`의 yaml 등 md가 아닌 파일은 제외).
   - `$ARGUMENTS`가 있으면: **단일 문서 모드** — 경로면 그 파일, 이름이면 `design/**`에서 매칭되는 md를 찾습니다 (예: `combat` → `design/gdd/combat.md`). 매칭이 여러 개면 AskUserQuestion으로 선택받고, 없으면 후보 목록을 보여줍니다.

2. **상태 진단:** 각 대상 md에 대해 대응 html(`design/html/` 미러 경로)을 확인해 분류합니다:
   - **누락** — html이 없음
   - **스테일** — md가 html보다 최신 (수정 시각 비교)
   - **최신** — 재생성 불필요
   - 추가로 **고아 html** 탐지: `design/html/**/*.html`(index 제외) 중 대응 md가 없는 것.

3. **재생성 (자동 — 별도 승인 불필요):**
   - 누락·스테일 문서를 `${CLAUDE_PLUGIN_ROOT}/docs/output-policy.md` 절차대로 재생성합니다 — md 전체를 다시 렌더하고, 시각 표현 어휘집 트리거도 다시 적용해 덮어씁니다.
   - 전체 동기화 모드에서 "최신" 문서는 건너뜁니다. 단일 문서 모드에서는 최신이어도 **강제 재생성**합니다 (사용자가 명시 지정한 것이므로 — 템플릿/어휘집이 갱신된 뒤 새 스타일을 반영하는 용도).

4. **고아 html 처리:** 고아가 있으면 목록을 보여주고 AskUserQuestion으로 삭제 여부를 확인합니다 (옵션 예: `삭제 (권장)` / `유지`). 임의로 삭제하지 않습니다.

5. **인덱스 재생성:** 변경이 하나라도 있었으면(또는 인덱스가 없거나 스테일이면) `design/html/index.html`을 output-policy 「인덱스 페이지」 절차로 전체 재생성합니다.

6. **결과 리포트:**

   ```
   ## HTML 동기화 결과
   - 재생성: N개 (누락 a, 스테일 b, 강제 c)
   - 최신 유지: M개
   - 고아 html: K개 (처리 내역)
   - 인덱스: 재생성됨 / 이미 최신
   표시본 열기: design/html/index.html
   ```

**유저 결정 질문 규칙 (필독):**
- 문서명 매칭 모호·고아 html 삭제 등 유저 결정이 필요한 질문은 **AskUserQuestion 도구**로 묻습니다. (상세: `${CLAUDE_PLUGIN_ROOT}/docs/decision-policy.md`)

**산출물 출력 규칙 (필독):**
- html 생성 절차·시각 표현·인코딩(UTF-8, BOM 없이)은 `${CLAUDE_PLUGIN_ROOT}/docs/output-policy.md`를 반드시 따릅니다.
- 이 커맨드는 **정본 md를 수정하지 않습니다.** md 내용에 문제가 보이면 고치지 말고 리포트에서 언급만 합니다.

**활용 예:**
- `/gdd-html` — 전체 점검·동기화 (인덱스 누락, html 스테일 일괄 복구)
- `/gdd-html combat` — 전투 GDD 표시본만 강제 재생성 (+ 인덱스)
- 템플릿·시각 어휘집이 업데이트된 플러그인으로 갈아탄 뒤 기존 문서 표시본을 새 스타일로 일괄 리프레시할 때도 사용
